## Prioritized blockers and fixes

1. **P1 — Name the actual source editors.** **Observed** `/new`, Paste → `.cm-content[role=textbox]`: accessibility tree calls it only “textbox”; the visible `<label for="body">` still targets the hidden textarea. **Source:** `web/editor/editor.js:mount` transfers the placeholder but no accessible label; editor body/widget use the same island. Pass stable `aria-labelledby`/`aria-label` through `EditorView.contentAttributes`, and associate inline error/help text with the contenteditable. Verify distinct “Artifact source” and “Gallery widget source” names as well as “HTML source” on creation.

2. **P1 — Make creation validation and pending state reliable.** **Observed** `/new`, blank Paste/URL → `#status`: “Paste an artifact first.” / “Enter a URL first.” appear in ordinary body styling; focus stays on Add to library. **Source:** `new.tmpl` has no live/error semantics on `#status`; `new.js:ingest` has no in-flight guard or control lock, and `setMode` retains the previous method's status. Use field-level errors with `aria-invalid`/`aria-describedby`, focus the invalid field, and announce progress/outcomes. Disable/guard submission and incompatible mode changes until the request settles, restore controls on failure, and reset method-specific feedback on switching. Successful creation/double-submit outcomes were not tested.

3. **P1 — Let version history reflow on phones. Source inference.** `/artifacts/:id/edit` → `#versions-panel .version-row`: `edit.css` keeps sequence, a nonwrapping full UTC timestamp, View and Restore in one flex row; `.version-when` and `.version-seq` cannot shrink and no phone wrapping rule exists. At 320px the nested panel has roughly 240px of content width. A historical row's fixed content is likely wider even before its title. Stack metadata and wrap the actions, with usable touch heights; verify a populated history at 320/390px and enlarged text. Do not treat the present fixture's untested history as a visual pass.

4. **P2 — Give the app's primary context and actions visible labels.** **Observed** `/`: Accounts has a full label, Add artifact is only a secondary plus, desktop card titles are 12.5px, and action triggers are invisible at rest (expand to only 22×20px on hover). Keep an identifiable action affordance without layout shift, strengthen card-name typography, and give Add artifact clear primary emphasis/desktop text. **Source inference:** viewer `#pip-title` renders posture/caret only; actual title lives in hidden `#pip-info`. Show a shortened artifact name or an equally clear context affordance, and offer a readily discoverable Edit action while retaining the full artifact canvas.

5. **P2 — Unify overflow interaction and touch sizing. Source finding.** Card overflow uses `action-menu-controller.js` with arrow/Home/End/typeahead/focus-out handling. Viewer `#pip-more`/`#pip-menu` in `pip.js` only implements popup opening and Escape; keyboard focus can leave without dismissing. `components.css` gives viewer buttons 36px on coarse pointers and the restore tab only 20px width, versus 44px gallery controls. Reuse the shared action-menu behavior where appropriate, dismiss on focus exit, and enlarge phone hit areas without obscuring content. Verify keyboard return, touch dismissal and restore-tab access at both phone sizes.

6. **P2 — Finish empty/result feedback and control contrast.** **Observed** search miss/shared empties are isolated sentences with substantial unused space. Make search/filter misses a shared full-width partial with contextual query/filter summary and a nearby Clear search/Reset filters action; explain how shared artifacts arrive. **Source:** `gallerygrid.tmpl` has no results live region or first-page pending indicator, unlike its paging status; add a concise announced result count/state and restrained pending feedback. `tokens.css` input border `#ddd` against white is about **1.36:1**, and dark `#41464f` against `#202328` about **1.67:1**; strengthen boundaries where they identify controls, retaining the otherwise readable text palette.
