# Per-owner agent spend cap: refuse before the spend, not after

Once [[av-siqf]] lets an instance supply the provider credential, an agent session spends the operator's money with nothing bounding it. Sessions are long-lived, steered by model output, and can loop; the idle timeout reaps an *inactive* session, which is the opposite failure. There is no ceiling per turn, per session, per owner, or per instance.

Billing does not fix this and should not be expected to. Usage-based billing invoices what happened — by the time a meter reading becomes an invoice line the money is spent, and on a free tier there is no invoice at all. The cap has to be enforced ahead of the spend, in-process, and it has to hold when every external service is unreachable.

## Design

**Check before spawn and again between turns.** `agentSessionOpts` (`internal/api/agent.go:148`) is the single place both session creators resolve a credential, so the pre-spawn check has one home. The between-turns check belongs in `internal/agent` beside the readLoop, because a session that is already running is the one that runs away.

**Mid-turn is the honest hard part, and its answer depends on [[av-2yws]].** If Pi reports usage only at turn end, the finest enforcement possible is per-turn, and a single pathological turn is unbounded. Say so explicitly rather than implying a tighter guarantee than the protocol supports; if that gap is unacceptable, the fallback is a wall-clock or tool-call ceiling per turn, which bounds the damage without needing token counts at all.

**Layered limits, because they fail differently.** A per-owner budget over a period is the product-level limit and maps to a plan ([[av-2p8z]]). A per-session ceiling catches a loop inside one conversation without waiting for the period budget to drain. An instance-wide ceiling is the backstop against a mistake in the other two, and it is the only one that protects against a novel failure nobody predicted — set it, and alert on it.

**Refuse legibly, and never mid-thought if avoidable.** A user who hits the budget gets a clear message about a limit and when it resets, not a stalled stream or a generic error. A session stopped between turns should leave the artifact in whatever state the last successful save left it — the artifact is durable and the transcript is persisted, so stopping is recoverable in a way silently continuing is not.

**Absent configuration means no limit for sessions the operator does not pay for.** A self-hosted instance is unaffected, and so is a BYO-key session anywhere: a user spending their own tokens is not the operator's exposure and must not be throttled by the operator's default.

**But platform mode may not run uncapped.** Where [[av-siqf]]'s platform credential is configured and no cap is, the server **fails at startup** — the same fail-closed posture [[av-2p8z]] takes for entitlements, and for a sharper reason: the resource being spent is money, and the failure is unbounded rather than merely large. This supersedes av-siqf's startup warning, which was the right answer only while no cap existed to require. The distinction is the same one throughout: absence of the *feature* is unlimited, absence of a *limit the feature requires* is a refusal to boot.

**Landing this makes the sequencing structural rather than remembered.** Once platform mode without a cap cannot boot, "do not expose platform mode to public signups before the cap exists" stops being a note in a ticket that someone has to read.

## Acceptance Criteria

- With no cap configured and no platform credential, agent behavior is identical to today.
- BYO-key sessions are never limited by the operator's defaults, on any instance.
- A platform credential configured with no cap fails at startup, and av-siqf's warning for that case is removed as superseded.
- With a per-owner budget configured, a session is refused before spawn when the owner is over it, with a message naming the limit and its reset.
- A running session is stopped at the first opportunity after the owner crosses the budget, and the enforcement granularity the protocol actually permits is documented rather than implied.
- A per-session ceiling stops a looping conversation without waiting for the owner's period budget.
- An instance-wide ceiling refuses new sessions and is logged loudly when reached.
- A stopped session leaves the artifact on its last successful save and the transcript intact.
- Enforcement holds with the payment provider unreachable.
