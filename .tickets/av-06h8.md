# CSP download support

Support configuration of CSP that doesn't violate policy on download actions. Must configure flag 'allow-downloads'.


## Notes

**2026-08-05T04:48:45Z**

Delivered by a different mechanism than this ticket prescribed. Downloads work from the render iframe via the host-frame capability bridge in the render preamble (internal/render/render.go): blob:/data: anchor exports (and the File System Access polyfill) are intercepted, posted to the host frame pinned to the app origin, and the host — authenticated, same origin as the API — performs the download after a first-use approval prompt. Approval persists as artifacts.downloads_approved (migration 005) and is revocable from the edit page's capability panel.

'allow-downloads' is deliberately NOT granted on the sandbox: doing so would give artifact code unmediated download authority, whereas the bridge keeps the opaque-origin sandbox intact and makes each artifact's download capability an explicit, revocable per-artifact decision. Vectors the bridge misses stay sandbox-blocked, which is the safe default. Covered by internal/api/downloads_test.go and the render tests; documented in architecture.md §6 and security.md §4.
